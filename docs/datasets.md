# Give datasets stable names

A logical dataset is the name your ETL code uses. The name should describe the data, not the file format or database
where it happens to live today.

Good names include:

- `CLAIMS.CLAIM_LINE`
- `EHR.PATIENT`
- `REFERENCE.PROVIDER`

`CLAIMS.CLAIM_LINE_CSV` is usually a poor name because “CSV” is temporary implementation detail.

## Write a logical dataset name

Every name has two uppercase parts separated by a period:

```text
SUBJECT_AREA.DATASET_NAME
```

The first part groups related data. The second part names one dataset in that group. You can create one directly:

```python
dataset = etlonomy.DatasetId(
    subject='CLAIMS',
    name='CLAIM_LINE',
)

assert str(dataset) == 'CLAIMS.CLAIM_LINE'
```

Direct construction is fine in a small script or framework test. In an application, repeated strings are easy to
mistype. Etlonomy can generate Python names from the catalog instead.

## Generate Python names from the catalog

```console
etlonomy codegen datasets \
  --database .etlonomy/catalog.db \
  --output src/claims_demo/datasets.py
```

The output resembles:

```python
"""Generated by ETLonomy; do not edit manually."""

from etlonomy import DatasetId


class _Claims:
    """Datasets in the CLAIMS subject area."""

    # jobs can import this stable name instead of repeating a path or string
    CLAIM_LINE = DatasetId('CLAIMS', 'CLAIM_LINE')


class Datasets:
    """Generated logical dataset namespace."""

    CLAIMS = _Claims()
```

The same catalog produces the same file. Commit it when applications import the generated package. Regenerate it when
you add or remove logical dataset names.

You do **not** need to regenerate it when a dataset moves from CSV to SQL. Its logical name stayed the same.

## Ask for logical columns

```python
from claims_demo.datasets import Datasets

claims_read = etlonomy.read(
    Datasets.CLAIMS.CLAIM_LINE,
    # these are logical names; a version may map them to different source names
    'person_id',
    'diagnosis_code',
)
```

The request contains no rows. It simply tells the provider which dataset and columns to load later.

## Choose column names that can last

Use names that make sense to downstream code. If one legacy source calls a column `member_id` and a newer source calls
it `patient_identifier`, both can map to the logical name `person_id`. This keeps transformations readable and prevents
source renames from spreading through the codebase.

The mapping belongs on each source version. You will see that in
[file sources](files.md#rename-source-columns).
